# Phase-Two Plan v4 — Switch-Level INC with First-Class Packet Type

*Proposal v4. Supersedes `v3.md` on §2.7, §3.2, §3.3,
§3.4, §3.5, §4, §5, §10. The (β) tree replication choice (§3.1)
and the (m')/RPF dispatch model (§3.6) are unchanged from v3 — the
core idea remains "one undirected tree per group, RPF dispatch."
What changes is the **packet and sink representation**: instead of
hacking multicast through the unicast machinery (dst-range encoding
+ host-FIB rewrite), v4 introduces first-class INC primitives.*

*Five concrete changes from v3:*

1. *New packet class `UecMcastPacket : public Packet`. Multicast
   packets carry an explicit group identifier and operation type;
   the dst-range encoding (`MCAST_BASE | group_idx`) is removed.*
2. *New per-switch `INCFib` keyed by `group_id`, separate from the
   existing unicast `_fib`. Cleaner separation; no namespace
   collision between unicast and multicast destinations.*
3. *Leaf-TOR delivery via a new sink class `UecMcastSink`,
   registered per-(host, group). The leaf-TOR `_dst`-rewrite-and-
   re-inject dance is removed; replicas reach the right sink via
   pre-baked routes.*
4. *Operation-agnostic base classes `UecCollectiveSrc` and
   `UecCollectiveSink` capture the machinery common to every
   collective primitive (per-op state map, ACK-less emission,
   completion-trigger plumbing). Phase 2 implements
   `UecBcastSrcMcast` / `UecMcastSink` as subclasses. Phase 3
   adds `UecReduceSrc` / `UecReduceSink` and Allgather variants
   as peers, reusing the base-class bookkeeping.*
5. *Path-derived `_pathid` via a deterministic running hash of
   `(group_id, source_host_id, egress-port sequence)`. The naïve
   `pkt.pathid() + branch_idx` approach (used in v3) collides
   across multi-hop fanout; an earlier static-counter draft fixed
   uniqueness but produced different ids for the same physical
   path across distinct operations. The running hash guarantees
   **same path → same `_pathid`** across operations, which is
   what trace tools actually need (§3.2.1).*

*Why both changes now: v3's dst-range encoding was always
temporary — phase three's aggregation needs new packet fields
(operation type, sequence number, partial-reduction state) that
the proposal explicitly calls out as deliverable §3.2 ("integrating
multicast/aggregation metadata support into the htsim packet
format"). Doing the packet-format work in phase two costs ~1 extra
day of design + implementation but saves more than that in phase
three (no migration from dst-range to packet-type) and produces a
cleaner, more intuitive design throughout. Phase three's reduce
packet (`UecReducePacket`) becomes a peer of `UecMcastPacket`
rather than a retrofit.*

*No code has been written. Please approve, amend, or reject.*

| Aspect | v3 | v4 |
|---|---|---|
| Multicast signal in packet | `_dst >= MCAST_BASE` (high-bit reserved range) | New packet class `UecMcastPacket` with explicit `_group_id` field |
| FIB key for multicast | `mcast_dst(group_idx) = MCAST_BASE \| group_idx`, in same map as unicast | `group_idx` directly, in a separate `INCFib` per switch |
| Multicast/unicast dispatch | dst-range check at FIB lookup | Packet-type check at top of `receivePacket` |
| Leaf-TOR delivery | Rewrite `_dst` to host_addr, re-inject through `getNextHop`, hit hostfib | Pre-baked route ending at `UecMcastSink` per (host, group); no rewrite, no re-injection |
| Sink type | `UecBcastSink` registered per-(member, op) under op-level flow_id | `UecMcastSink` registered per-(host, group) at `set_up_mcast` time; per-op state in a small map keyed by `op_flow_id` |
| Source/sink shared machinery | None — `UecBcastSrc` and `UecBcastSink` each carry their own bookkeeping | `UecCollectiveSrc` / `UecCollectiveSink` base classes capture the per-op state map, ACK-less emit, completion-trigger plumbing; phase-2 and phase-3 sub-classes only override packet-type-specific hooks |
| Per-leaf-TOR FIB content | `tree_port_mask` + sparse `host_rewrites: vector<pair<port_idx, host_addr>>` | `tree_port_mask` + sparse `leaf_routes: vector<pair<port_idx, Route*>>` |
| `_pathid` semantic | `pkt.pathid() + branch_idx` — collides across multi-hop fanout | Path-derived running hash: same physical path → same `_pathid` across all operations |
| Phase-3 packet-format work | Deferred entirely | Foundation laid in phase two; phase three adds `UecReducePacket` as a peer |
| §3.2 / §3.5 / §3.7 recommendation flips | (ii) reserved range / (x) rewrite / per-class machinery | (i') new packet class / (z) new mcast-aware sink / common collective base classes |

**Why both flips now**: v3 §3.2 and §3.5 each took the "minimum
diff" option — reuse `_dst` and `_fib` for multicast, reuse
`UecBcastSink` and hostfib at leaf TORs. Both are minimum-diff in
*phase two only*. In phase three, both reverse: aggregation
*must* carry partial-reduction state in the packet (proposal
§3.2), so the dst-range encoding becomes redundant; aggregation
*must* deliver to a per-(group, root) sink that knows how to
combine partial inputs, so the leaf-TOR rewrite becomes
redundant. Doing the work once cleanly in phase two, with phase
three already in mind, saves one round of refactoring.

The phase-one harness (the parser, BarrierTrigger plumbing,
BcastCompletionRecorder) is unchanged. The phase-one
`UecBcastSrc` and `UecBcastSink` remain in use for `-bcast_mode
baseline`. Phase two adds new classes for `-bcast_mode mcast`
without touching the baseline path.

## 2. Ground Truth from the Codebase

*(Sections 2.1–2.6 unchanged from v3; only 2.7 substantively
updated.)*

### 2.1 Switch forwarding is two-stage and strictly unicast

`FatTreeSwitch::receivePacket` (`fat_tree_switch.cpp:23`) runs a
two-step pipeline per packet: ingress (FIB lookup, route attach,
pipe delay) then egress (sendOn). The FIB
(`RouteTable::_fib : unordered_map<int, vector<FibEntry*>*>`,
`routetable.h:52`) is destination-keyed. Packets carry single-path
state and take exactly one route per hop.

`getNextHop(Packet&, BaseQueue* ingress_port)` already accepts an
ingress argument but `receivePacket` calls it with `NULL`. v4's
RPF dispatch threads the ingress through.

Critically, `receivePacket` already special-cases `ETH_PAUSE` at
the top via `pkt.type() == ETH_PAUSE` (`fat_tree_switch.cpp:24`).
**v4 follows this exact pattern for `UEC_MCAST` packets**: a top-of-
function type check that diverts INC traffic to a dedicated
handler before the standard ingress/egress pipeline runs.

### 2.2 `FatTreeTopology::set_up_mcast` is a stub, correctly placed

Defined at `fat_tree_topology.cpp:596`, called from
`main_uec.cpp:781` after topology construction and `conns->groups`
attachment but before per-flow source/sink instantiation. Under
v4 this ordering is **load-bearing for sink creation**: v4 creates
`UecMcastSink` instances at `set_up_mcast` time (one per (host,
group)), so `set_up_mcast` runs first and the per-op driver loop
just registers expectations.

### 2.3 Packet refcount exists but cannot be used for fanout

`PacketDB::inc_ref_count`/`dec_ref_count` (`network.h:164–166`)
plus the freelist (`network.h:299–305`) would in principle allow
shared-pointer fanout. **It doesn't work** because `Packet` fuses
body and per-recipient state. Real ASICs separate body (shared
SRAM cell, refcounted) from descriptor (per-egress metadata);
htsim doesn't, so each replica must be its own packet. v4 keeps
v2's recommendation: distinct copies via a new factory.

### 2.4 No pre-existing multicast or aggregation anywhere

Searched all transports and queue types. No replication, fanout,
or multicast routing outside the stub. **No reduction/aggregation
primitive of any kind.** Phase two and phase three are both
from-scratch extensions.

### 2.5 The collective-input format (`.cm`) accepts `start_bcast` only

`connection_matrix.cpp:761` parses `start_bcast`. No
`start_reduce`, `start_allreduce`, `start_allgather` tokens exist
yet. Phase three extends the parser.

### 2.6 `Switch::_ports` provides stable port indices

`Switch::addPort` (`switch.cpp:12`) appends to `_ports` and returns
the index. Each queue gets `setSwitch(this)`. Port indices are
stable for the simulation lifetime.

`fat_tree_topology.cpp` per-tier asserts:
- TOR: `addPort(...) < 96`
- AGG: `addPort(...) < 64`
- CORE: `addPort(...) < 64`

Implication for FIB representation: port indices fit in `uint8_t`;
bitmap representation must accommodate 96 bits → `std::bitset<128>`.

### 2.7 `Packet` subclassing pattern, packet-type enum, and PacketDB

This section is **substantively expanded in v4** because phase
two now relies on it.

`Packet` (`network.h:83–226`) is the base class for all htsim
packet types. The `_type` field is a `packet_type` enum
(`network.h:38–39` area) with values like `IP`, `UEC`, `UECACK`,
`UECNACK`, `ETH_PAUSE`, `NDP`, `ROCE`, etc. **A new value `UEC_MCAST`
must be added to this enum** for phase two.

Existing UEC subclasses (`UecPacket`, `UecAck`, `UecNack` in
`uecpacket.h`) follow a consistent pattern:

1. Inherit from `Packet`.
2. Hold their own `static PacketDB<T>` for object pooling.
3. Provide static `newpkt(...)` factories that allocate via
   PacketDB and set `_type` appropriately.
4. Implement `free()` returning the object to the freelist.
5. Override `priority()` to declare queue-priority class.

`UecMcastPacket` follows this pattern exactly (see §3.2 below).

**Packet-type dispatch sites** to verify (most pass `Packet&`
generically and don't need updating):

- Queue types (`compositequeue.cpp`, `randomqueue.cpp`, etc.):
  receive `Packet&`; route by `_size` and `priority()`. No change
  needed for `UEC_MCAST`.
- `FatTreeSwitch::receivePacket`: already type-checks for
  `ETH_PAUSE`; v4 adds the `UEC_MCAST` arm at the same site.
- Tracing/logging: typically dispatches on `_type`; v4 may need
  to add a string label for `UEC_MCAST` in trace pretty-printing.

Phase three extends with `UecReducePacket` (peer class with
partial-reduction state field) and a new enum value `UEC_REDUCE`.

### 2.8 Consequence for the v4 design

The cleanest insertion point remains `FatTreeSwitch::receivePacket`,
now with three top-level branches: `ETH_PAUSE` (existing),
`UEC_MCAST` (new in phase two), unicast fallthrough (existing).
The `UEC_MCAST` arm dispatches via the new `INCFib` keyed by
`pkt.group_id()`, computes the egress mask via `tree_port_mask &
~(1 << ingress_idx)`, and spawns replicas via
`UecMcastPacket::newpkt_replica`. At leaf-TOR member ports, the
replica's route terminates at the `UecMcastSink` registered for
(host, group) — no rewrite, no re-injection.

## 3. Design Decisions

### 3.1 Where does replication happen?

*(Unchanged from v3.)* **Recommended: (β) tree replication.**

### 3.2 How does a packet signal "I need multicast fanout"? — **flipped from v3**

**Three candidates** revisited:

- **(i) New `Packet::ptype` value, `UEC_MCAST`, plus dedicated
  packet class `UecMcastPacket`.** Switch dispatches at top of
  `receivePacket` based on type, exactly mirroring `ETH_PAUSE`
  handling. Packet carries explicit `_group_id` and `_op_type`
  fields.
- **(ii) Reserved destination-address range.** v3's choice. Group
  identifiers live in `_dst` bits above `MCAST_BASE`. FIB lookup
  reuses `_fib`.
- **(iii) Flag on the packet (e.g., bool `_is_mcast`)**. Always
  rejected as redundant with the FIB.

**Recommended: (i) new packet class `UecMcastPacket` with type
`UEC_MCAST`.** v4 flips from v3's (ii).

#### Why the flip

v3's (ii) was justified as the minimum-diff option for phase two
in isolation. The justification breaks once phase three is in
scope:

1. **Aggregation requires new packet fields anyway.** Phase three
   needs partial-reduction state in the packet (a small operand
   carried alongside the body), an operation sequence number to
   disambiguate concurrent aggregations on the same group, and a
   reduction-root identifier for Reduce/Allreduce. The proposal
   §3.2 explicitly calls this out as deliverable §3.2 ("integrating
   multicast/aggregation metadata support into the HTSIM packet
   format"). v3's dst-range encoding doesn't fit any of these —
   it claims one bit of `_dst` and ignores everything else.

2. **The dispatch logic is cleaner with type-based discrimination.**
   `if (pkt.type() == UEC_MCAST) handle_mcast(pkt)` is one branch,
   typed, immediately understood by anyone familiar with htsim's
   `ETH_PAUSE` pattern. `if (is_mcast_dst(pkt.dst())) ...` requires
   knowing the encoding convention and is one bit-arithmetic check
   away from a silent collision with a unicast destination.

3. **Type-safety at C++ level.** `static_cast<UecMcastPacket*>(&pkt)`
   after a type check gives compile-checked access to `group_id()`,
   `op_type()`, etc. Under (ii) the equivalent is `pkt.dst() &
   ~MCAST_BASE` — manual decoding with no compiler help.

4. **Trace and log integration.** Existing logging machinery
   pretty-prints by packet type. `UEC_MCAST` is one-line added to
   the type-name table. Under (ii) traces show generic `UEC` packets
   with strange `_dst` values that need explanation.

5. **Phase-three composability.** `UecReducePacket` becomes a peer
   class with type `UEC_REDUCE`, same pattern. Three packet types
   side-by-side handle multicast / reduce-up / reduce-down.
   Under (ii)'s extension path, you'd partition the `_dst` bit
   range further (multicast vs aggregation vs allreduce-phase-A
   vs allreduce-phase-B) — a brittle convention layer growing on
   top of an already-fragile encoding.

#### The packet class

```c
class UecMcastPacket : public Packet {
public:
    typedef uint64_t seq_t;

    // Phase-2 fields (always populated):
    seq_t _seqno;
    uint32_t _group_id;       // identifies the multicast group

    // Phase-3 forward-compatibility fields (zero in phase 2):
    // - op_seq_id: per-operation sequence to disambiguate
    //   concurrent aggregations on the same group
    // - reserved for future packet-format extensions
    uint32_t _op_seq_id;

    // Constants
    constexpr static int acksize = 64;

    UecMcastPacket() : Packet() {}
    virtual ~UecMcastPacket() {}

    // Mixing constants for path-derived _pathid (see §3.2.1).
    static constexpr uint32_t PATHID_SEED_MIX = 2654435761u;  // Knuth golden ratio mix
    static constexpr uint32_t PATHID_HOP_MIX  = 31u;          // standard hash chaining

    // Source-side factory: build a fresh multicast packet from a
    // UecBcastSrcMcast at the start of an operation. The initial
    // _pathid is seeded from (group_id, source_host_id) so all
    // packets emitted by the same source on the same group share
    // the same starting hash.
    inline static UecMcastPacket* newpkt(
            PacketFlow& flow, const Route& route,
            seq_t seqno, int size,
            uint32_t group_id, uint32_t source_host_id,
            uint32_t op_seq_id = 0) {
        UecMcastPacket* p = _packetdb.allocPacket();
        // Wire size is data payload + header overhead, matching
        // UecPacket convention. _id is the last data byte
        // (seqno + size - 1), independent of header.
        p->set_route(flow, route, size + acksize, seqno + size - 1);
        p->_type = UEC_MCAST;
        p->_is_header = false;
        p->_bounced = false;
        p->_seqno = seqno;
        p->_group_id = group_id;
        p->_op_seq_id = op_seq_id;
        p->_pathid = (group_id ^ source_host_id) * PATHID_SEED_MIX;
        p->_direction = NONE;
        // _dst is left at the default; group_id drives dispatch.
        return p;
    }

    // Switch-side factory: spawn a replica for fanout. The
    // replica's _pathid is the parent's hash mixed with the
    // egress port index, so replicas that ultimately traverse
    // identical paths receive identical _pathids — even across
    // distinct multicast operations on the same group from the
    // same source. See §3.2.1 for properties.
    inline static UecMcastPacket* newpkt_replica(
            UecMcastPacket& source,
            const Route& branch_route,
            uint8_t egress_port_idx) {
        UecMcastPacket* p = _packetdb.allocPacket();
        p->set_route(source.flow(), branch_route,
                     source.size(), source.id());
        p->_type = UEC_MCAST;
        p->_is_header = false;
        p->_bounced = false;
        p->_seqno = source._seqno;
        p->_group_id = source._group_id;
        p->_op_seq_id = source._op_seq_id;
        p->_pathid = source._pathid * PATHID_HOP_MIX
                     + static_cast<uint32_t>(egress_port_idx) + 1u;
        p->_direction = NONE;
        p->from = source.from;
        p->to = source.to;
        p->tag = source.tag;
        return p;
    }

    void free() { _packetdb.freePacket(this); }

    inline uint32_t group_id() const { return _group_id; }
    inline seq_t seqno() const { return _seqno; }
    inline uint32_t op_seq_id() const { return _op_seq_id; }

    virtual int data_packet_size() const { return _size; }
    virtual PktPriority priority() const { return Packet::PRIO_LO; }

private:
    static PacketDB<UecMcastPacket> _packetdb;
};
```

#### §3.2.1 Path-derived `_pathid` — same path → same id, across operations

Two earlier approaches were considered and rejected:

- **`pkt.pathid() + branch_idx`** (v3): collides across multi-hop
  fanout because each switch restarts `branch_idx` at zero.
- **Static monotonic counter** (earlier v4 draft): unique per
  *packet*, but the same physical path traversed by two different
  multicast operations gets two different `_pathid` values. Trace
  tools can't correlate per-path behaviour across ops.

**Recommended: derive `_pathid` deterministically from the path
itself**, by hashing the egress-port sequence chosen at each
fanout switch. Concretely:

- **Source-side seed** mixes `group_id` and the source host ID,
  so all packets from the same source on the same group start
  from the same hash seed:
  ```
  _pathid_source = (group_id XOR source_host_id) × 2654435761
  ```
- **Per-hop update** at each fanout switch mixes the parent's
  pathid with the chosen egress port index:
  ```
  _pathid_replica = _pathid_parent × 31 + egress_port_idx + 1
  ```

`2654435761` is Knuth's golden-ratio multiplicative constant;
`31` is the canonical small-prime hash chaining mix.

#### Properties

| Scenario | Result |
|---|---|
| Same group, same source, same fanout sequence | identical `_pathid` end-to-end |
| Same group, same source, different fanout sequence (different leaf) | divergent `_pathid` after first differing hop |
| Different sources, same group | different seeds → different `_pathid` end-to-end |
| Different groups | different seeds → different `_pathid` |
| **Same path, two different operations** | **identical `_pathid`** (the headline property) |

This means trace analysis can correlate "everything that ever
traversed path X" across a sweep of multicast operations: same
physical path produces the same `_pathid`, regardless of
allocation order.

#### Properties not provided

- **Bijective decoding from pathid back to path**: a 32-bit hash
  is lossy; given a `_pathid`, the path that produced it cannot
  be recovered without an external table. Acceptable for tracing
  (we look up per-path behaviour by computing the hash from the
  path, not the reverse).
- **Zero collision guarantee**: two distinct paths can in
  principle collide. Probability ≈ 1/2³² per pair of unrelated
  paths; for ~10⁶ distinct paths in a thesis sweep, expected
  collisions are well below 1.
- **Per-packet uniqueness within an operation**: under the
  single-MTU thesis assumption a source emits exactly one packet
  per op, so the question doesn't arise. If multi-MTU streams
  are added later, combine `_pathid` with `_seqno` for full
  identity.

#### Why this is better than alternatives

| Alternative | Problem |
|---|---|
| `pkt.pathid() + branch_idx` | Collides across multi-hop fanout. |
| Static monotonic counter | Same path, two ops → different ids; no cross-op correlation. |
| Hash including `op_seq_id` | Reintroduces the per-op variation we want to eliminate. |
| `(group_id, source, dest_host)` triple as the path id | Dest is unknown at interior switches; only resolvable at the leaf. The egress-port hash sidesteps this — interior replicas have a partial-path hash that fully extends to the leaf hash by the time they're delivered. |

**Memory footprint per packet**: `UecPacket`'s footprint plus 4
bytes (`_group_id`) plus 4 bytes (`_op_seq_id`). The phase-3 field
`_op_seq_id` is small enough that pre-allocating it in phase two
costs little; saves the migration in phase three.

**No `_dst` rewrite logic anywhere.** `_dst` is unused by INC
packets (it's left at default `UINT32_MAX` from the base
constructor). Dispatch is driven by `_type`, `_group_id`, and
ingress port — no `_dst` reading on the INC path.

**No `MCAST_BASE` constant**. Removed from the design.

### 3.3 FIB representation — refined from v3

**Recommendation unchanged in shape (port bitmap), refined in
container**: `INCFibEntry` lives in a new per-switch `INCFib`,
keyed directly by `group_id` (a 32-bit unsigned integer, not a
synthesized dst).

```c
class INCFibEntry : public FibEntry {
public:
    // Multicast tree: bit i set ↔ Switch::_ports[i] is in this group's
    // tree at this switch. Used by:
    //   - Multicast / Allgather: replicate to (mask & ~ingress).
    //   - Aggregation / Reduce: input ports = (mask & ~root_port_idx).
    std::bitset<128> tree_port_mask;

    // For leaf-TOR member ports: pre-baked route terminating at
    // the (host, group)'s UecMcastSink. Sparse — keyed by
    // port_idx; one entry per local member host.
    // Empty at interior switches (use _port_egress_routes instead).
    std::vector<std::pair<uint8_t, Route*>> leaf_routes;

    // PHASE 3 ONLY: which port leads "toward root" for a reduce-
    // direction op. nullopt at the root switch and at switches
    // not participating in reduce ops.
    std::optional<uint8_t> root_port_idx;

    // Defensive override against legacy ECMP code paths.
    Route* getEgressPort() override {
        assert(0 && "INCFibEntry has fanout/aggregation semantics");
        return nullptr;
    }

    // Dispatch helper: returns the leaf route for a given port,
    // or nullptr if the port is interior at this switch.
    Route* leaf_route_for(uint8_t port_idx) const {
        for (auto& [idx, r] : leaf_routes)
            if (idx == port_idx) return r;
        return nullptr;
    }
};

class INCFib {
public:
    INCFibEntry* lookup(uint32_t group_id) const {
        auto it = _entries.find(group_id);
        return it == _entries.end() ? nullptr : it->second;
    }
    void install(uint32_t group_id, INCFibEntry* entry) {
        _entries[group_id] = entry;
    }
private:
    std::unordered_map<uint32_t, INCFibEntry*> _entries;
};
```

`FatTreeSwitch` gains an `INCFib* _inc_fib;` member alongside the
existing `_fib` (RouteTable). `_fib` is unchanged; unicast traffic
sees no behavioural difference.

**Why this shape (vs. v3's `host_rewrites`)**: under v3, leaf-TOR
delivery required a `host_rewrites` map mapping port_idx →
host_addr, plus `_dst`-rewrite-and-re-inject through `getNextHop`,
plus a hostfib lookup against the rewritten `_dst` and the
op-level flow_id. Five steps to deliver to a sink whose identity
was knowable at install time. Under v4, the leaf-TOR
`INCFibEntry` carries the route directly — three elements (queue,
pipe, sink) — and dispatch is one step: spawn replica with that
route.

The `Route*` in `leaf_routes` is owned by the `INCFibEntry` (or by
a per-switch route pool); built once at `set_up_mcast` time and
reused for every multicast operation on this group.

#### Memory comparison

For a leaf TOR with K=16, group with 4 members on this TOR:

| Shape | Per-FIB-entry leaf state |
|---|---|
| v3 `host_rewrites` | 4 × (1B port_idx + 4B host_addr) = 20 bytes |
| v4 `leaf_routes` | 4 × (1B port_idx + 8B Route*) = 36 bytes |
| Plus the Route objects themselves (3 PacketSink* each) | 4 × ~32 bytes = 128 bytes |

v4 trades ~150 bytes per leaf-TOR INCFibEntry for elimination of
all leaf-TOR rewrite logic. Across a 1024-node fat-tree with ~100
groups: ~15 MB extra in process memory. Negligible.

### 3.4 Packet replication mechanism — simplified

Distinct copies, as before. The dispatch logic at switches becomes
strikingly simple under v4:

```c
void FatTreeSwitch::receivePacket(Packet& pkt) {
    if (pkt.type() == ETH_PAUSE) {
        /* ... existing code ... */
        return;
    }

    // NEW: INC packets bypass the unicast pipeline entirely.
    if (pkt.type() == UEC_MCAST) {
        handle_mcast(static_cast<UecMcastPacket&>(pkt));
        return;
    }

    // Existing unicast path:
    if (_packets.find(&pkt) == _packets.end()) {
        _packets[&pkt] = true;
        const Route* nh = getNextHop(pkt, NULL);
        pkt.set_route(*nh);
        _pipe->receivePacket(pkt);
    } else {
        _packets.erase(&pkt);
        pkt.sendOn();
    }
}

void FatTreeSwitch::handle_mcast(UecMcastPacket& pkt) {
    INCFibEntry* entry = _inc_fib->lookup(pkt.group_id());
    if (!entry) {
        // Should not happen if set_up_mcast ran for this group.
        pkt.free(); return;
    }

    if (_packets.find(&pkt) == _packets.end()) {
        // Ingress: fanout dispatch.
        uint8_t ingress_idx = identify_ingress_port_idx(pkt);
        std::bitset<128> egress_mask = entry->tree_port_mask;
        egress_mask.reset(ingress_idx);

        for (size_t i = 0; i < 128; ++i) {
            if (!egress_mask.test(i)) continue;
            Route* leaf = entry->leaf_route_for(i);
            const Route& route = leaf ? *leaf : *_port_egress_routes[i];

            UecMcastPacket* replica = UecMcastPacket::newpkt_replica(
                pkt, route, /*egress_port_idx=*/static_cast<uint8_t>(i));
            // _pathid is derived from the parent's hash mixed
            // with this egress port index (see §3.2.1) — same
            // path → same id across distinct operations.
            replica->set_direction(NONE);
            _packets[replica] = true;
            _pipe->receivePacket(*replica);
        }
        pkt.free();   // symmetric: original freed; all egress
                      // copies are fresh allocations
    } else {
        _packets.erase(&pkt);
        pkt.sendOn();
    }
}
```

**No rewrite. No re-injection. No hostfib pollution.** The mcast
packet keeps `_group_id` and `_op_seq_id` intact through every
replication; at a leaf TOR member port, the replica's route ends
at the `UecMcastSink` directly, which receives the packet with
all INC fields preserved.

### 3.5 Leaf-TOR delivery — flipped from v3 to (z) new sink

**Three candidates**:

- **(x) Rewrite `_dst` to host_addr at the leaf TOR.** v3's
  recommendation. Rejected in v4 because it forces multicast
  through the unicast hostfib, requires a rewrite map, and
  re-injection through `getNextHop`.
- **(y) Per-host `INCFibEntry` egress routes whose terminator
  is resolved at install time.** Defeats per-group state — sinks
  are per-(host, op), so per-(host, op) FIB entries.
- **(z) New `UecMcastSink` registered per-(host, group); leaf-TOR
  routes terminate at it directly.** v4's recommendation.

**Recommended: (z) `UecMcastSink`.**

```c
class UecMcastSink : public UecSink {
public:
    UecMcastSink(int host_addr, uint32_t group_id)
        : UecSink(), _host_addr(host_addr), _group_id(group_id) {
        _nodename = "uec_mcast_sink";
    }

    void receivePacket(Packet& pkt) override {
        if (pkt.type() != UEC_MCAST) { pkt.free(); return; }
        UecMcastPacket& mp = static_cast<UecMcastPacket&>(pkt);

        // Optional sanity check (only fires under bug):
        // assert(mp.group_id() == _group_id);

        auto it = _per_op.find(mp.flow_id());
        if (it == _per_op.end()) {
            // Driver didn't register this op for this sink — drop.
            mp.free(); return;
        }
        OpState& s = it->second;

        s.bytes_received += mp.data_packet_size();
        mp.free();

        if (!s.completed && s.bytes_received >= s.expected_bytes) {
            s.completed = true;
            if (s.end_trigger) s.end_trigger->activate();
        }
    }

    // Driver per-op registration. Called once per multicast op
    // that targets this (host, group). Idempotent.
    void register_op(uint32_t op_flow_id,
                     uint64_t expected_bytes,
                     Trigger* end_trigger) {
        _per_op[op_flow_id] = {0, expected_bytes, end_trigger, false};
    }

private:
    int _host_addr;
    uint32_t _group_id;
    struct OpState {
        uint64_t bytes_received;
        uint64_t expected_bytes;
        Trigger* end_trigger;
        bool completed;
    };
    std::unordered_map<uint32_t, OpState> _per_op;
};
```

**Sink lifecycle**:
- Created once per (host, group) at `set_up_mcast` time.
- Lives for the simulation lifetime.
- Per-op state added incrementally via `register_op` as the
  driver schedules each multicast operation.
- One sink absorbs many concurrent or sequential ops on the same
  (host, group).

**`addMcastPort` helper on `FatTreeSwitch`**: registers the
(host, group) sink and builds the corresponding leaf-TOR route:

```c
void FatTreeSwitch::addMcastPort(int host_addr, uint32_t group_id,
                                 UecMcastSink* sink) {
    // Build the route to this sink.
    uint8_t port_idx = host_downlink_port_idx(host_addr);
    Route* r = new Route();
    r->push_back(_ports[port_idx]);                            // queue
    r->push_back(get_pipe_for_port(port_idx));                 // pipe
    r->push_back(sink);                                         // sink
    // Install in this switch's INCFibEntry for this group.
    INCFibEntry* entry = _inc_fib->lookup(group_id);
    assert(entry && "INCFib entry must exist before addMcastPort");
    entry->leaf_routes.emplace_back(port_idx, r);
    // Verify the bit is set in tree_port_mask:
    assert(entry->tree_port_mask.test(port_idx) &&
           "addMcastPort: leaf port not in tree_port_mask");
}
```

#### Why this is structurally cleaner than v3

| Concern | v3 (rewrite) | v4 (sink) |
|---|---|---|
| Multicast packet's `_dst` | mutated at leaf TOR | unused on INC path |
| Lookups per replica at leaf TOR | 2 (re-injection through `getNextHop` + hostfib) | 0 (route pre-baked) |
| Code paths multicast vs unicast share | hostfib (uneasily) | none |
| Sink type | `UecBcastSink` (phase 1's class, registered per-op) | `UecMcastSink` (semantic, persistent per-group) |
| Sink lifecycle | Per-op | Per-(host, group), shared across ops |
| Allgather sink complexity | |G|-1 sinks per member per op | One sink absorbs |G|-1 concurrent ops |

### 3.6 Tree granularity

*(Unchanged from v3.)* **Recommended: (m') one undirected tree per
group, RPF dispatch.** Structurally necessary for grade 5.25
(Allgather/Allreduce); also matches ASIC multicast representation.

The tree-construction algorithm (§5 step 4) produces a
deterministic, root-agnostic, undirected, acyclic tree per group.

### 3.7 Naming & transport-class decomposition — operation-agnostic base classes

**Recommendation refined from v3**: introduce **operation-
agnostic base classes** `UecCollectiveSrc` and `UecCollectiveSink`
that capture the machinery common to every collective primitive,
with operation-specific subclasses (`UecBcastSrcMcast` /
`UecMcastSink` in phase 2; `UecReduceSrc` / `UecReduceSink` and
peers in phase 3) only differing in **what packet type they emit
or accept**.

#### What's common across collective sources

- One source per operation; ACK-less (received packets dropped).
- Triggered by `activate()` or `doNextEvent()` at the operation's
  scheduled start time.
- Carries op-level `flow_id` via `_flow`.
- Has a group identity (`_group_id`).
- Emits exactly once per op — single-MTU thesis assumption.
- Connects via `connect(srctotor_route, /*routeback=*/nullptr,
  dummy_sink, start_time)`.

#### What's common across collective sinks

- Per-op state map keyed by `op_flow_id`, holding
  `(bytes_received, expected_bytes, end_trigger, completed)`.
- `register_op(op_flow_id, expected_bytes, end_trigger)` for
  driver-side per-op registration.
- Discards packets of unexpected type or unknown op.
- Fires `end_trigger` exactly once when expected bytes received.

#### What differs per source / sink

- **Source**: which packet class to allocate
  (`UecMcastPacket` vs `UecReducePacket` vs ...).
- **Sink**: which packet type to accept; how to interpret the
  body (mere byte-counting for multicast vs partial-aggregate
  combination for reduce).

#### The base classes

class UecCollectiveSink : public UecSink {
public:
    UecCollectiveSink(int host_addr, uint32_t group_id)
        : UecSink(), _host_addr(host_addr), _group_id(group_id) {}

    // Driver registration. Idempotent.
    void register_op(uint32_t op_flow_id,
                     uint64_t expected_bytes,
                     Trigger* end_trigger) {
        _per_op[op_flow_id] = {0, expected_bytes, end_trigger,
                               false};
    }

    // Common dispatch shell — type-check, op-lookup,
    // delegate to subclass for body interpretation.
    void receivePacket(Packet& pkt) override {
        if (!accepts_packet_type(pkt)) { pkt.free(); return; }
        if (pkt.header_only())          { pkt.free(); return; }

        auto it = _per_op.find(pkt.flow_id());
        if (it == _per_op.end())        { pkt.free(); return; }
        OpState& s = it->second;

        process_body(pkt, s);   // subclass-specific; calls free()

        if (!s.completed && s.bytes_received >= s.expected_bytes) {
            s.completed = true;
            if (s.end_trigger) s.end_trigger->activate();
        }
    }

    int host_addr() const { return _host_addr; }
    uint32_t group_id() const { return _group_id; }

protected:
    // Subclass: which packet type(s) does this sink accept?
    virtual bool accepts_packet_type(const Packet& pkt) const = 0;

    // Subclass: body-specific update. Updates s.bytes_received;
    // for aggregating sinks, also combines partial state. Must
    // free the packet.
    virtual void process_body(Packet& pkt, struct OpState& s) = 0;

    int _host_addr;
    uint32_t _group_id;

    struct OpState {
        uint64_t bytes_received = 0;
        uint64_t expected_bytes = 0;
        Trigger* end_trigger = nullptr;
        bool completed = false;
    };
    std::unordered_map<uint32_t, OpState> _per_op;
};

## 4. Chosen Architecture

Stitching the v4 recommendations together:

1. **Source.** `UecBcastSrcMcast : public UecSrc` (new class in
   `uec_bcast.{h,cpp}`) emits exactly one `UecMcastPacket` per
   `.cm` broadcast entry. Source's `_flow` carries op-level
   `flow_id`. Packet's `_group_id = group_idx`.

2. **Packet.** `UecMcastPacket : public Packet` (new class in
   `uecpacket.h`) — first-class multicast packet with
   `_group_id`, `_op_seq_id`, `_seqno`. Type tag `UEC_MCAST`.
   Own PacketDB pool. No `_dst` use on INC path.

3. **Sink.** `UecMcastSink : public UecSink` (new class in
   `uec_bcast.{h,cpp}`) registered per-(host, group) at
   `set_up_mcast` time via new `FatTreeSwitch::addMcastPort`.
   Per-op expectations registered incrementally via
   `register_op(op_flow_id, expected_bytes, barrier)`.

4. **FIB.** Per-switch `INCFib` keyed by `group_id`, separate
   from the existing `_fib` (RouteTable). Holds `INCFibEntry`
   instances with `tree_port_mask` (bitmap), `leaf_routes`
   (sparse pre-baked routes to sinks at leaf TORs), and
   `root_port_idx` (phase 3 only, nullopt in phase 2).

5. **Switch dispatch.** `FatTreeSwitch::receivePacket` gains a
   third top-level branch (after `ETH_PAUSE` handling) that
   detects `UEC_MCAST` packets and routes them to
   `handle_mcast`. The unicast pipeline is unchanged.
   Ingress port identification via the same route-inspection or
   reverse-map technique as v3 (cached
   `unordered_map<BaseQueue*, uint8_t>` populated alongside
   `_ports`).

6. **Topology setup.** `FatTreeTopology::set_up_mcast` walks
   `conns->groups`. For each group:
   - Build a deterministic, root-agnostic, undirected tree
     (algorithm §5 step 4).
   - Create one `INCFibEntry` per switch on the tree, keyed by
     `group_idx`. Set `tree_port_mask` bits.
   - For each member host: create one `UecMcastSink`; register
     it at the host's leaf TOR via `addMcastPort(host,
     group_idx, sink)`. This populates `leaf_routes` with the
     route ending at the sink.
   - Verify invariants: the resulting per-switch port sets,
     viewed as an undirected graph, form a tree; every
     leaf-TOR member port has a `leaf_route` entry whose
     terminator is a `UecMcastSink` for the right host.

7. **Driver.** `-bcast_mode {baseline,mcast}` CLI flag in
   `main_uec.cpp`. In `mcast` mode:
   - Locate the per-(host, group) `UecMcastSink` instances created
     by `set_up_mcast` (e.g., via a new
     `FatTreeTopology::get_mcast_sink(host, group_idx)` accessor).
   - For each member ≠ root: call
     `sink->register_op(op_flow_id, crt->size, barrier)`.
   - Allocate one `UecBcastSrcMcast`, set `_group_id =
     group_idx`, set `_dstaddr` unused (or mark as 0xDEADBEEF
     sentinel).
   - Connect via the standard route-to-TOR mechanism. The
     source's first packet enters the root TOR with
     `_type = UEC_MCAST` and `_group_id = group_idx`; from there,
     `handle_mcast` takes over.
   - BarrierTrigger and BcastCompletionRecorder unchanged from
     phase one.

#### v3 → v4 driver-side refactor

The v4 driver flow is **slightly more involved** than v3 because
sink creation moves to `set_up_mcast` and per-op registration
becomes a separate driver step:

```c
// At main_uec.cpp around line 781:
top->groups = &(conns->groups);
top->set_up_mcast();   // NOW: builds INCFibEntries + creates
                       // UecMcastSink per (host, group) +
                       // populates leaf_routes

// In the per-op is_bcast loop:
if (crt->is_bcast && bcast_mode == MCAST) {
    BarrierTrigger* barrier = /* same as v3 */;
    barrier->add_target(*new BcastCompletionRecorder(...));

    // Register per-op expectations on each member's persistent sink:
    for (int32_t m : group) {
        if (m == root) continue;
        UecMcastSink* sink = top->get_mcast_sink(m, group_idx);
        sink->register_op(op_flow_id, crt->size, barrier);
    }

    // Create and connect the source:
    UecBcastSrcMcast* bs = new UecBcastSrcMcast(...);
    bs->set_group_id(group_idx);
    bs->set_flow_id(op_flow_id);
    bs->setFlowSize(crt->size);
    bs->connect(srctotor, /*routeback=*/nullptr, /*sink=*/dummy,
                crt->start);

    // No addHostPort needed for mcast sources — source emits
    // directly with _type = UEC_MCAST; root TOR's handle_mcast
    // takes over from the first hop. addHostPort for sinks is
    // also gone; addMcastPort handled it during set_up_mcast.
}
```

The split between "persistent per-(host, group) state" and
"per-op expectations" mirrors how real INC frameworks (SHARP)
distinguish job-launch tree setup from per-collective operation
state. Cleaner architectural shape; same total lines of code.

## 5. Implementation Plan

Ordered for independent testability.

1. **Packet-type registration** *(small, ~1h)*.
   - Add `UEC_MCAST` to the `packet_type` enum.
   - Update any tracing/logging type-name tables if present.
   - Unit test: round-trip of `UEC_MCAST` through a stub queue.

2. **`UecMcastPacket`** *(small, ~3h)*.
   - New class in `uecpacket.h` per §3.2.
   - Static `PacketDB<UecMcastPacket> _packetdb` definition in
     `uecpacket.cpp`.
   - Two factories per §3.2 / §3.2.1:
     - `newpkt(flow, route, seqno, size, group_id,
       source_host_id, op_seq_id=0)` — source-side; sets the
       initial path-hash seed `(group_id ^ source_host_id) ×
       2654435761`.
     - `newpkt_replica(source, branch_route, egress_port_idx)` —
       switch-side fanout; updates the path-hash via
       `parent_pathid × 31 + egress_port_idx + 1`.
   - `priority()` override.
   - Unit tests:
     - Alloc/free round-trip; field copying via
       `newpkt_replica`.
     - **Path-hash determinism**: hand-build a two-hop fanout
       (switch A egress port = 5; switch B egress port = 2);
       compare the leaf replica's `_pathid` against the value
       computed manually as `seed × 31 + 5 + 1) × 31 + 2 + 1`.
     - **Cross-op pathid stability**: emit two source packets
       with the same `(group_id, source_host_id)`; trace both
       through the same two-hop fanout; assert leaf replicas
       have **identical** `_pathid` (the headline §3.2.1
       property — same path, two operations, same id).

       `size = 4096`; assert `pkt.size() == 4096 + acksize`

     ```
     members     = groups[group_idx]
     member_tors = { HOST_POD_SWITCH(h) for h in members }
     member_pods = { HOST_POD(h)        for h in members }
     podpos      = group_idx % agg_switches_per_pod()

     for tor in member_tors:
         agg_in_pod = MIN_POD_AGG_SWITCH(HOST_POD(tor)) + podpos
         tor's tree:
             - host downlink for each local member
             - uplink to agg_in_pod (if pod has multiple
               member_tors OR group is multi-pod)

     for pod in member_pods:
         agg = MIN_POD_AGG_SWITCH(pod) + podpos
         agg's tree:
             - downlinks to each member_tor in pod
             - uplink to chosen_core (if multi-pod)

     if multi_pod:
         uplink_bundles = radix_up(AGG_TIER) / bundlesize(CORE_TIER)
         core_offset    = (group_idx / agg_switches_per_pod())
                          % uplink_bundles
         chosen_core    = core_offset * agg_switches_per_pod()
                          + podpos
         core's tree:
             - downlink to chosen AGG in each member_pod
     ```
   - Edge cases: all-on-one-TOR (no AGG/Core); single-pod (no
     Core); 2-tier topology (no Core).
   - Invariant check: per-switch port sets form an undirected
     acyclic tree.
   - Unit tests: K=4 cross-pod, intra-pod, intra-TOR; verify
     same tree results from multiple sources (root-agnostic
     property).

9. **`FatTreeTopology::set_up_mcast` body** *(moderate, ~6h)*.
   - For each `group_idx` with `groups[group_idx].size() >= 2`:
     - Call `build_mcast_tree(group_idx)`.
     - Per switch on the tree: instantiate `INCFibEntry`, set
       bits in `tree_port_mask`, install in switch's `_inc_fib`
       under `group_idx`.
     - Per member host: instantiate `UecMcastSink(host_addr,
       group_idx)`; call leaf-TOR's `addMcastPort(host_addr,
       group_idx, sink)`.
     - Stash sinks in a topology-level
       `unordered_map<pair<int, uint32_t>, UecMcastSink*>` so
       the driver can later call `register_op`.
   - Run leaf-TOR consistency assertion (every leaf-TOR member
     port has a matching `leaf_route`).

10. **Driver integration** *(simplified relative to v3, ~6h)*.
    - Add `-bcast_mode {baseline,mcast}` CLI flag.
    - In `is_bcast` branch: dispatch on mode.
    - `mcast` mode: per-op registration via
      `top->get_mcast_sink(m, group_idx)->register_op(...)`; one
      `UecBcastSrcMcast` per op; standard barrier wiring.
    - Removed: `next_bcast_leg_flow_id` machinery, `addHostPort`
      calls for mcast (handled by `addMcastPort` in
      `set_up_mcast`).

11. **Benchmark extension** *(unchanged from v3, ~3h)*.

12. **Thesis doc updates** *(documentation, ~6h)*.

13. **Regression check** *(~3h)*.
    - Baseline mode bit-identical to pre-phase-two.
    - Mcast mode: completion time dominated by max-leaf path
      latency.
    - v4-specific: same group sourced from two different roots
      uses the same `INCFibEntry` and same `UecMcastSink`s;
      different ops on same group disambiguated by op_flow_id at
      sinks.

**Total estimate**: ~40–50 hours for phase two (vs. v3's ~30–40h).
The extra ~10 hours buys the packet-format work that the proposal
schedules anyway, plus the sink-type cleanup. Within the 90h

## 7. Risks and Open Questions

- **Concurrent broadcasts share interior tree links.** Same risk
  as v3.

- **Bitmap–leaf-routes synchronization.** `tree_port_mask` and
  `leaf_routes` must agree at leaf TORs (every host-port bit set
  in mask must have a matching `leaf_routes` entry). v4 asserts
  this once at end of `set_up_mcast`.

- **Ingress port identification correctness.** Same as v3:
  route-inspection assumes the standard 3-element route shape.

- **`_direction` state machine on replicas.** Same as v3: tree-
  shape geometry guarantees no `DOWN→UP` transitions.

- **`UecMcastSink` per-op state lookup overhead.** Each received
  packet does a small `unordered_map<uint32_t, OpState>` lookup.
  Negligible at thesis scale; flagged for awareness.

- **`register_op` ordering hazard.** If the driver calls
  `register_op` *after* the source has already emitted, early
  packets find no per-op state and silently drop. Mitigation:
  driver discipline + assertion that per-op state exists when
  `BcastCompletionRecorder::activate()` fires (i.e., the barrier
  expects |G|-1 fires; if any sink missed registration, it never
  fires, and the recorder's failure mode is detectable).
  Stronger mitigation: assert that `register_op` is called
  *before* `bs->connect()` in the driver, since `connect()` is
  what schedules the source's first emission.

- **Phase-3 dependency lock-in.** v4 commits to the
  `UecMcastPacket`/`UecMcastSink`/`INCFib` shape under the
  assumption that aggregation will reuse it cleanly. §10 walks
  through the validation. If phase three discovers a
  fundamentally different need (e.g., requires per-port priority
  ordering in the bitmap), some redesign is needed — but the
  packet-class and FIB-class boundaries are robust to most
  field-level extensions.

- **Time-budget pressure.** v4's phase-two estimate (~40–50h)
  consumes more of the 90h weeks-4–8 budget than v3's (~30–40h).
  Trade-off: v4's extra time front-loads work the proposal
  scheduled for phase three. Net for the full thesis: same
  hours, better-shaped intermediate states.

- **Phase-4 hazard: trim/retransmit on aggregation paths.**
  Under finite buffers (a phase-4 concern, out of scope here),
  a trimmed-and-retransmitted aggregation packet whose original
  reached the aggregator and was already counted will silently
  corrupt the partial reduction unless the aggregator
  deduplicates. Fraschetti's PR #1 has this bug
  (`uec_inc_src.cpp:190` retransmits with `_inc_int_data = 1`
  "dummy data" rather than the original payload, masking the
  symptom). v4's recommended `ReduceState.received_from`
  (a `set<contributor_id>` rather than an integer counter,
  borrowed from Fraschetti — see §10.1) is duplicate-tolerant,
  so a deduplicated retransmit is safely a no-op. Worth keeping
  in mind when phase 4 turns on finite buffers.

- **Removed risks**: v3's "set_up_mcast / sink-registration
  ordering" risk is eliminated because v4's `set_up_mcast`
  creates sinks. v3's "leaf-TOR rewrite logic correctness" risk
  is eliminated because the rewrite no longer exists. v3's
  "MCAST_BASE safety vs. topology node count" risk is eliminated
  because the dst-range encoding no longer exists.

## 9. Stopping Here for Approval

Please review v4 specifically against v3. Pointed questions:

1. **The packet-type-now move**: is the cost (~+10h in phase two)
   worth the benefit (cleaner abstraction now, no migration in
   phase three, contributes to deliverable §3.2 early)? Or is it
   premature when phase 3 isn't fully scoped yet?

2. **`UecMcastPacket` field reservation**: the class includes
   `_op_seq_id` (a phase-3 field, unused in phase 2). Adding it
   now keeps the wire format stable; alternative is to add it in
   phase 3 with a tiny rev. Acceptable to allocate the field
   now?

3. **`INCFib` separation vs. extending `_fib`**: v4 puts the
   multicast FIB in a separate per-switch object. Alternative is
   to add an `INCFibEntry` variant to `_fib`'s vector. Separation
   is cleaner; extension is fewer LoC. Preference?

4. **Sink lifecycle across operations**: v4's `UecMcastSink` is
   persistent per-(host, group) and absorbs multiple ops via the
   per-op map. Alternative is one sink per (host, op),
   consistent with phase-one's UecBcastSink pattern, but defeats
   the simplification. Acceptable?

5. **`addMcastPort` as a new switch-API method**: adds a peer to
   `addHostPort`. Acceptable, or fold into a generalized
   `addPort` API?

6. **Time-budget realism**: phase-two ~40–50h; phase-three
   ~40–50h within the 90h weeks-4–8 budget. Tight but feasible.
   Acceptable, or do we descope (e.g., target grade 5.0 instead

## 10. Phase 3 Preview: How v4 Extends to Aggregation, Reduce, Allreduce, Allgather

This section is forward-looking; it validates that v4's packet/sink/
FIB shape generalizes cleanly to phase three. Not part of phase-
two deliverables.

### 10.1 Aggregation primitive at the switch

A new packet class `UecReducePacket : public Packet`, peer to
`UecMcastPacket`:

```c
class UecReducePacket : public Packet {
public:
    typedef uint64_t seq_t;

    seq_t _seqno;
    uint32_t _group_id;
    uint32_t _op_seq_id;
    uint32_t _reduction_root_host;   // which host is the destination
    uint64_t _partial_payload;        // small partial-reduction operand
                                       // (for thesis: single primitive value)
    uint8_t _op;                       // SUM/MIN/MAX/...

    constexpr static int acksize = 64;

    UecReducePacket() : Packet() {}

    inline static UecReducePacket* newpkt(...);    // source-side
    inline static UecReducePacket* newpkt_aggregated(...);  // switch-side

    void free() { _packetdb.freePacket(this); }
    virtual PktPriority priority() const { return Packet::PRIO_LO; }

private:
    static PacketDB<UecReducePacket> _packetdb;
};
```

**Switch dispatch** extends `receivePacket` with a fourth top-level
arm:

```c
if (pkt.type() == UEC_REDUCE) {
    handle_reduce(static_cast<UecReducePacket&>(pkt));
    return;
}
```

`handle_reduce` uses the **same `INCFib`** (lookup by
`pkt.group_id()`) and the **same `INCFibEntry`** (now with
`root_port_idx` populated). Per-active-op state shape is borrowed
from Fraschetti's `AggregationEntry` (HLC-Lab/uet-htsim PR #1,
`inc_switch.h:12-16`) — one of the few patterns in that PR worth
reusing:

```c
struct ReduceState {
    std::set<uint32_t>      received_from;     // contributor host ids
                                                //   (duplicate-tolerant)
    simtime_picosec         first_arrival;     // free instrumentation
    /* operator-specific partial-reduction operand */
};

void FatTreeSwitch::handle_reduce(UecReducePacket& pkt) {
    INCFibEntry* entry = _inc_fib->lookup(pkt.group_id());
    uint8_t ingress_idx = identify_ingress_port_idx(pkt);
    auto key = std::make_pair(pkt.group_id(), pkt.op_seq_id());

    auto [it, fresh] = _reduce_state.try_emplace(key);
    ReduceState& state = it->second;
    if (fresh) state.first_arrival = eventlist().now();

    state.received_from.insert(pkt.contributor_host_id());
    state.aggregate(pkt._partial_payload, pkt._op);
    pkt.free();

    size_t expected = entry->tree_port_mask.count() - 1;
    if (state.received_from.size() == expected) {
        UecReducePacket* out = UecReducePacket::newpkt_aggregated(
            state, *_port_egress_routes[*entry->root_port_idx]);
        _packets[out] = true;
        _pipe->receivePacket(*out);
        _reduce_state.erase(key);   // explicit lifecycle: alloc on
                                     //   first arrival, free on last
    }
}
```

Three properties this state shape gives us, all from the
Fraschetti review:

1. **`set<contributor_id>` instead of integer counter** —
   duplicate-tolerant. If a retransmit ever delivers a partial
   value twice (phase 4 with finite buffers), `insert` is a no-op
   and the count stays correct. Cheap defense even though phase 3
   under (A3) doesn't model retx.
2. **`first_arrival` timestamp** — per-block latency for free; the
   natural anchor for any future timeout machinery.
3. **Explicit `_reduce_state.erase(key)` on completion** —
   Fraschetti's bug was a `_completed_blocks` set that grew
   unbounded because they only inserted, never deleted
   (`inc_switch.cpp:64`). We delete on completion. Phase 3 should
   define this as a hard invariant and assert it with periodic
   bounds checks during long simulations.

**Reuses from phase two**:
- `INCFib`, `INCFibEntry`, `tree_port_mask` — unchanged.
- Ingress port identification — unchanged.
- `_port_egress_routes` cache — unchanged.
- `set_up_mcast` (renamed `set_up_inc` if preferred) — extended
  with `root_port_idx` install per (group, reduction-root).
- Switch top-level dispatch — gains one arm.

**New in phase three**:
- `UecReducePacket` class.
- `_reduce_state` map per switch (per-active-op state).
- Reduction-operator implementations.
- Driver branch for `start_reduce` connections.
- New `UecReduceSrc : public UecCollectiveSrc` (overriding
  `emit_once`) and `UecReduceSink : public UecCollectiveSink`
  (overriding `accepts_packet_type` for `UEC_REDUCE` and
  `process_body` to also inspect partial payloads). Both reuse
  the `UecCollectiveSrc` / `UecCollectiveSink` base classes
  introduced in phase two (§3.7) — **no new sink/source
  bookkeeping code needed**, only operation-specific overrides.

### 10.2 Reduce collective

Many-to-one. Each member emits a `UecReducePacket` with its partial
value. Tree converges via `handle_reduce` at AGG/Core. Root TOR
delivers the final aggregated packet to `UecReduceSink` for
(reduction-root-host, group).

**Two ways to compute "where does up-aggregation stop and result
delivery begin?"**:

- **Install-time `root_port_idx`** (recommended): each switch's
  `INCFibEntry` carries an explicit
  `optional<uint8_t> root_port_idx` per (group, reduction-root)
  pair, set by `set_up_inc` from a known root host. O(1)
  per-packet decision.
- **Runtime LCA detection** (Fraschetti's approach,
  `inc_switch.cpp:87-93`): each switch checks "is every
  participant downstream of me?" If yes, this is the LCA — emit
  the result without forwarding up. If no, forward up. Useful
  when the root is not known at install time, or when the LCA
  is irregular (e.g. a `reduce` operation rooted at the LCA
  rather than at a specific host). The check is O(participants)
  per completing block; for thesis-scale groups (<= a few
  thousand hosts) this is fine.

The install-time approach is simpler and faster, and we have the
information at `set_up_inc` time. The runtime LCA pattern is kept
in this document as a fallback if a future use case (e.g.
ad-hoc Reduce trees not pre-installed) needs it.

`root_port_idx` is per (group, reduction-root-host). Stored as
a per-(group, root) map of `unordered_map<int_root_host_id, uint8_t
port_idx>` per switch, OR as a per-(group, root) sub-table in the
INCFibEntry. Either works; phase three picks. The per-group
`tree_port_mask` is shared across all reduction-roots — each root
just selects a different exit point from the same tree.

### 10.3 Allreduce collective

Two phases on the **same `INCFibEntry`**:

- Phase A (reduce up): `UecReducePacket` traffic; uses
  `tree_port_mask` minus `root_port_idx`.
- Phase B (multicast down): `UecMcastPacket` traffic from the
  reduction root; uses `tree_port_mask` minus ingress (RPF).

Same FIB serves both phases; the dispatch differs by packet type.
**Zero extra FIB state** for Allreduce vs. Reduce + Bcast
separately.

### 10.4 Allgather collective

|G| pipelined `UecMcastPacket` broadcasts on the same per-group
tree. **No new switch-side code.** The orchestration layer
schedules |G| `UecBcastSrcMcast` instances per group, one per
member. Each member's `UecMcastSink` registers |G|-1 ops (one per
other member's broadcast).

**Cost**: ~50 lines of driver + parser code (`start_allgather`
token); no FIB changes; no packet-class changes.

This is the cheapest grade-5.25 milestone. v4 makes it nearly
free.

### 10.5 Validation summary

The v4 design supports:

- ✅ Multicast / Broadcast (phase 2): `UecMcastPacket`,
  `tree_port_mask`, `leaf_routes`.
- ✅ Reduce: `UecReducePacket`, `tree_port_mask` reused,
  `root_port_idx` added.
- ✅ Allreduce: phase A + phase B on same FIB; same
  `INCFibEntry`.
- ✅ Allgather: |G| `UecMcastPacket` broadcasts on same FIB;
  zero switch-side change.

**Conclusion**: v4 is forward-compatible with all four phase-three
operations the thesis targets. The packet-format work done now
(`UecMcastPacket`) becomes the foundation for `UecReducePacket`;
the sink/source shape (`UecCollectiveSink` / `UecCollectiveSrc`
base classes with per-op state maps and standard hooks) becomes
the foundation for `UecReduceSink` / `UecReduceSrc` and the
Allgather variants. The unique-`_pathid` mechanism (§3.2.1)
generalizes — phase three's `UecReducePacket` and any future
peer classes can use the same static-counter pattern (or, if
preferred, share a single counter across the INC packet family
via a `Packet`-base-level static).

No architectural rewrites between phase two and phase three —
only additive extensions of:
- enum values (`UEC_REDUCE` joins `UEC_MCAST`)
- packet classes (`UecReducePacket` joins `UecMcastPacket`)
- collective sink/source subclasses (extending the
  phase-2 base classes)
- switch dispatch arms (`handle_reduce` joins `handle_mcast`)
- FIB entry fields (`root_port_idx` becomes load-bearing)

This is the deepest argument for v4: the cost (~+10h in phase 2)
buys a phase-3 boundary that is purely additive. v3's phase-3
boundary required migrating the dst-range encoding to a packet
type and migrating the rewrite-and-reinject machinery to per-
(host, group) sinks — both of which are exactly the v4 changes.
v4 just does that work earlier, where it costs less to do
correctly because we're not also debugging multicast at the same
time.
